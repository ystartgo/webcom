雙引擎 AI 控制台・系統操作與排障手冊

四大推論模式說明 (1+1>2)

🖥️ LM Studio / API 模式

連接本地 LM Studio (Port 1234) 或雲端 API (OpenAI/Claude)，具備頂級代碼推論與複雜工具調度能力。

⚡ WebGPU 瀏覽器純本機

無需安裝任何後端軟體，模型權重直接跑在瀏覽器與顯示卡顯存上，零網路延遲、100% 離線隱私。

🧠 雙引擎聯合思考 (1+1>2)

第一階段 WebGPU 快速拆解意圖與假說，第二階段 主模型深度批判驗證與決策執行，發揮極致協同效能！

🛡️ 監督排查模式 (雙 LLM 互查)

當任一方卡死、回應空白、或程式碼出現明顯缺陷時，另一方將自動介入進行審查、點出盲點、並提出修正方案。適用於除錯、疑難排解、與穩定性要求高之場景。

常駐程式 (Port 8001 Daemon) 啟動

點擊頂部 `[▶ 啟動常駐程式]` ➔ `[確認一鍵重啟 / 啟用]`，系統將自動啟動後端，連線成功後視窗會自動關閉，並賦予 AI 控制本地終端機與硬體的能力。

模擬純斷網驗證開關 ⭐ 新功能

頂部工具列新增 `[外網：連通]` 開關。點擊後立即切換至 `[純斷網模擬：已啟動]`（按鈕呈紅色警示），前端將全域封鎖所有非 127.0.0.1 / localhost 的外部請求（含 CDN、GitHub、HuggingFace 等），讓您無需拔網路線即可即時驗證 100% 純離線 / WinPE 環境運作狀態。再次點擊即可一鍵恢復外網。

⚡ WebGPU 模型 — 首次下載後永久快取

首次選用 WebGPU 模型（如 Qwen2.5-0.5B 約 350 MB）時，模型權重會自動從 HuggingFace 下載並永久儲存於瀏覽器快取。之後無論是否斷網，均可 0 秒瞬間載入在顯卡上運算，不需重複下載！

什麼是 Artifact？獨立預覽沙箱

當要求 AI 產出完整的單檔網頁 (HTML/CSS/JS)、SVG 向量圖形、Markdown 報告或腳本時，AI 會以 <artifact> 標籤包裹輸出。系統會在對話框即時呈現高質感互動卡片，具備安全隔離沙箱 (iframe Sandbox)，免佈署、免伺服器即可直接在本機運行與互動！

多段智慧接續與無縫縫合 (避免字數上限中斷)

長程式碼（如 500+ 行應用）常因大語言模型單次輸出 Token 限制而被硬性打斷。Webcom 具備自動重疊去重縫合演算法：

  • 同名識別：後續輸出帶有相同 identifier 與 mode="continue" 時，系統自動定位主檔案。
  • 智能去重：自動比對前段結尾與後段開頭 1~25 行重疊部分及字元滑動去重，剔除重複行無縫拼接。
  • 緊湊接續卡片：後續對話以輕量卡片呈現「已自動接續合併至【標題】（新增 +X 行，總計 Y 行）」，拒絕冗餘刷屏。
  • 一鍵接續按鈕：若偵測到未完結，卡片底部直接提供「▶️ 一鍵接續生成 (Continue)」，自動引導 AI 輸出下一段。

版本控制與行級差異比對 (新功能！)

工坊內建完整的 Git 式版本歷程管理與一鍵還原機制：

  • 自動版本遞增：AI 首次產出為 v1，接續合併時自動建立 v2、v3，使用者編輯儲存時亦自動建立新版本。
  • 版本自由切換：透過標題列版本下拉選單，可隨時查看任意過去版本的程式碼與沙箱運行效果。
  • 一鍵安全還原 (Rollback)：檢視歷史版本時，點擊「還原此版」即可將檔案無損復原至該版本。
  • 自訂版本快照 (Snapshot)：點擊「📸 快照」按鈕，可為當前代碼狀態打上快照並加入專屬備註。
  • 行級差異比對 (Visual Diff)：點擊「比對 (Diff)」分頁，即時以綠色 (+) 標記新增、紅色 (-) 標記刪除，掌握所有改動細節！

用戶線上即時編輯與打字即時預覽 (Live Preview)

  • 卡片行內編輯：點擊對話卡片標題列的「✏️ 編輯」展開行內編輯框，支援 Tab 鍵 2 空格縮排。
  • 工坊並排即時預覽 (Live Preview)：點擊「開啟工坊」切換至「並排 (Split)」模式，打字修改時 iframe 沙箱 180ms 防抖即時更新渲染，完全所見即所得！
  • 安全儲存與還原：點擊「💾 儲存修改」同步全域檔案與對話卡片；改錯時隨時點擊「🔄 還原」一鍵退回 AI 初版。

Q1: LM Studio 提示 Failed to fetch / CORS 錯誤？

A: LM Studio 需允許跨域存取。請在終端機啟動：lms server start --cors --port 1234，或在 LM Studio 本地伺服器面板勾選 Enable CORS。亦可直接切換至「⚡ WebGPU 瀏覽器純本機」模式。

Q2: 常駐程式 (Port 8001) 連不上或被舊進程佔用？

A: 點擊頂部「常駐程式狀態」開啟面板，點擊 `[確認一鍵重啟 / 啟用]`，系統會自動強制終止佔用 8001 端口的舊行程並重新乾淨拉起服務。

Q3: WebGPU 模型下載進度與顯卡支援？

A: 首次使用 WebGPU 模型（如 Qwen2.5-0.5B 約 350MB）會自動下載並永久快取在瀏覽器中。支援 Chrome 113+ / Edge 等支援 WebGPU 的現代瀏覽器，推論時直接在顯卡上高速運算！

Q4: WebGPU 載入 3B 模型時閃退（exit code 1 / OOM）？

A: 顯存（VRAM）不足所致。解決方法：切換至較小的模型（推薦 Qwen2.5-0.5B 約 350MB），或關閉其他佔用 GPU 的應用程式後重試。若您的顯卡 VRAM 低於 4GB，建議改用 LM Studio / 後端 API 模式，將運算交給系統主記憶體處理。

Q5: LM Studio 回應時對話框空白但底部有 Token 統計？

A: 這是已知 DOM 節點脫離 Bug（v0.9.9 前舊版）。症狀：模型自動偵測到模型名稱時，舊版使用 innerHTML += 導致瀏覽器重建 DOM 並銷毀串流文字節點，回應全部寫入已脫離的無效節點，畫面空白但 token 統計有數值。此 Bug 已於 v1.0.0 修復，改用 insertBefore(badge, textBlock) 安全插入，串流渲染完整正常。請確保使用最新版本。

Q6: 切換語系（中↔英）後 AI 回應顯示 0 tokens？

A: 舊版切換語系時會插入語系提示詞至上下文（context），導致後端判斷 token 計算異常為 0。v1.0.0 已修復：語系切換僅更新 UI 顯示文字，不再汙染對話 context，AI 回應 token 統計完全正常。如仍遇到此問題，請點擊 「清除畫面」 重置對話後重試。

工作原理說明

WSL2 桌面運作方式：透過 Xvfb + x11vnc 在 WSL 內啟動 :1 虛擬顯示器並運行 XFCE4 視窗管理與桌面，監聽 5901 埠；同時透過 websockify 橋接為 WebSocket (6080) 與 HTTP 伺服器，前端即可透過 HTML5 Canvas 零延遲順暢操控！

方案一：完整桌面服務 (Xvfb + x11vnc + XFCE4 + websockify) 
# 1. 確保 /tmp/.X11-unix 具備讀寫權限
sudo mount -o remount,rw /tmp/.X11-unix
# 2. 啟動 Xvfb :1 與 x11vnc (DISPLAY=:1, Port: 5901)
nohup Xvfb :1 -screen 0 1920x1080x24 -ac ~/.vnc/xvfb.log 2>&1 &
env -u WAYLAND_DISPLAY x11vnc -display :1 -rfbport 5901 -nopw -listen 0.0.0.0 -forever -shared -bg -noxrandr
# 3. 啟動 XFCE4 桌面會話 (指定 X11 與 DISPLAY=:1)
nohup env -u WAYLAND_DISPLAY GDK_BACKEND=x11 DISPLAY=:1 QT_QPA_PLATFORM=xcb dbus-run-session -- xfce4-session ~/.vnc/xfce.log 2>&1 &
# 4. 啟動 WebSocket 橋接 (Port 6080 -> 5901)
websockify -D --web /usr/share/novnc 6080 localhost:5901
方案二：單一 GUI 程式 (Direct App) 
# 於 WSL 終端機中，直接將任意 Linux GUI 程式指向 DISPLAY=:1
export DISPLAY=:1
# 啟動終端機、檔案管理員或文字編輯器
xfce4-terminal &
thunar &
mousepad &
方案三：標準 Linux xinit / startx 會話 (已內建支援) 
# 支援標準 xinit / startx 指令（自動橋接虛擬 X 顯示器與 HTML5 視窗）
xinit                  # 啟動完整 XFCE 桌面會話
xinit xfce4-terminal   # 以 xinit 啟動獨立終端機
xinit thunar           # 以 xinit 啟動檔案總管
startx                 # 標準 startx 啟動
